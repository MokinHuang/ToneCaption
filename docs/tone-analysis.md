# ToneCaption 语气分析原理

> 对应代码：`src/lib/toneAnalysis.ts`（融合决策）、`src/lib/toneRules.ts`（文本规则）、`src/lib/pitch.ts`（句末音高）。
> 更新时间：2026-11-22（第二轮：纯标点字幕过滤；同段多句逐句判定与提示绑定）

## 1. 目标与定位

语气分析目前只判断一种语气：**「可能在征求确认」**——课堂上老师向学生求证、等待回应的问句（如"对不对""懂了吗""交作业了没有"）。

设计原则：

- **可解释**：每个结论都有人类可读的证据（原词摘录、音高测量值）与原因记录，进 UI 详情面板。
- **宁缺毋滥**：证据不足时宁可只留字幕，也不误报语气；拿不准时最多给"线索"而不猜语气。
- **绝不干扰主链路**：整个分析包在 try/catch 中，任何异常降级为"只留字幕"，不影响收音与转写；音高计算有 2 秒预算（`ANALYSIS_BUDGET_MS`），超时放弃。
- **纯前端**：全部在浏览器端完成，不依赖后端模型的情感输出。SenseVoice 声学情感仅作记录，不参与判断；说话人不明，不做跨句音量/语速比较。

## 2. 输入与输出

每段转写完成后触发一次分析，输入（`ToneAnalysisInput`）：

| 字段 | 说明 |
| --- | --- |
| `text` | 本段转写文本 |
| `prevTexts` | 本会话最近 2 句已完成文本（旧→新） |
| `pcm16k` | 本段 16kHz 单声道 PCM（Float32） |
| `cutReason` | 切段原因：`pause` / `max-length` / `stop` |
| `emotion` | SenseVoice 声学情感（仅记录） |

输出为**三态**：

1. **语气提示**：`tone = "可能在征求确认"` + 证据文本；
2. **仅线索**：`toneCue = "句末音高上扬"`，不下语气结论；
3. **只留字幕**：无 tone/toneCue，仅保留 `detail`（含未提示原因）。

`detail`（`ToneAnalysisDetail`）记录文本命中模式、摘录、抑制原因、音高测量或落空原因、上文提问、结论与理由，供 UI 展开查看。

输出还包含 **`sentences: SentenceTone[]`**：段内逐句结果，每句带 `text/start/end/complete` 原文范围。同段多句时（如"大家能接受吗？有冲突的下课来找我。"），提示按句子位置绑定——`LiveSegment.toneSentences` → `CaptionSegment.parts`，UI 分句渲染，「可能在征求确认」只挂在对应问句下，其余句单独显示字幕。顶层 `tone/evidence/toneCue/detail` 取第一个给出提示（或线索）的句子，供指标与详情表使用。

## 3. 三种证据

### 3.1 文本规则（toneRules.ts）

只检查**末尾小句**：先剥掉句尾标点，再按 `，、；：。？！` 等切出最后一个小句，在其中匹配确认类模式：

| 模式 | 示例 |
| --- | --- |
| 句尾疑问词「吗」 | 懂了吗 |
| 句尾求证词「吧」 | 这是对的吧 |
| 完成体正反问「了没有」 | 交作业了没有 |
| 正反问（枚举 + 通用 A不A） | 好不好 / 对不对 / 是不是 / 能不能 / 懂不懂… |
| 句尾正反问 | 行不 / 好不 / 对不 |

**误报排除**（命中后按顺序检查，任一成立即抑制并记录类别）：

- 「吧」的豁免：祈使（`下课吧/走吧/说吧`…）、达成体（`懂了吧/明白了吧`…）、光杆附和（`好吧/行吧/成吧`）不算求证；
- **引用抑制**（`quoted`）：命中词落在引号（`“”` `「」` `『』` `‘’` `""`）范围内；
- **反问抑制**（`rhetorical`）：强标记 `难道/岂/何必/何苦` 对任何命中生效；弱标记 `还不是/还不/不就/不都/这不是/那不是` 仅对「吗」命中生效（避免误伤"时间还不晚吧"类求证）。如"难道这还不明显吗"；
- **动作请求抑制**（`action-request`）：命中词之后出现 `把/帮/替/给/让`，或小句以「一下」收尾。如"能不能把窗户关一下"；真求证"能不能提前交"不受影响；
- **第一人称嵌入式疑问抑制**（`embedded-question`）：命中词之前有 `我/我们/咱(们) + ≤8 字 + 不知道/不清楚/不确定/没想好/没想过/问过/问了/说过/考虑过/琢磨/怀疑/担心/犹豫`。如"我昨天问过能不能补交""我也不知道这周五能不能交"；裸「说/问」不抑制——"我说这样行不行""我问能不能提前交"仍是向听众求证；
- **第三人称转述抑制**（`reported-speech`）：命中词之前的小句内有转述框架（`他/她/老师/同学们/某某同学… + ≤4 字间隔 + 问/说/问道/想知道/提到`）；
- **跨小句转述抑制**（`reported-speech`）：前一末尾小句以转述框架收尾（动词在句末，可带宾语代词，如"他问我，""老师问大家，"；第一人称仅限过去式"我问过，"），则当前小句属被转述内容。关键区分："老师说周五交，你们能接受吗"前句以「交」收尾而非转述动词，后半句是独立问句 → 正常提示，摘录来自"你们能接受吗"；
- **自动标点问号绝不单独触发任何判断**。

命中时生成 ≤14 字的原词摘录（保证是转写文本的子串）作为证据。

### 3.2 句末音高上扬（pitch.ts）

纯 Float32 数学，无 DOM 依赖，node 与浏览器双端可跑。目标：检测**跨音节的持续句末上扬**，同时拒绝普通话单字二声（100–200ms 升调）等假阳性。

**基频提取（YIN-lite 自相关）**：

- 40ms 帧，搜索 70–400Hz；差函数 + 累积均值归一（CMND），阈值 0.15，抛物线插值细化周期；
- 每 ~100 帧 `setTimeout(0)` 让出主线程，避免阻塞渲染；
- 后处理：半音域宽 3 中值滤波 → 邻域一致的倍频程误检剔除（>9st 且邻域 MAD 小）→ 相邻 >12st 跳变作废。

**两遍扫描**：

1. 整段粗扫（25ms 步长）→ `voicedEndMs` 找**真实语音结束点**（段末常带静音，尾窗必须锚定语音而非段末）；
2. 从结束点回溯 800ms 细扫（10ms 步长）得到尾窗轨迹。

**判定链（tailRise，任一不达标即返回 null + 原因）**：

| 检查 | 阈值 | 落空原因 |
| --- | --- | --- |
| 尾部连续浊音区（允许 ≤100ms 清音间隙，容纳 j/q/x/zh 声母） | ≥250ms 且 ≥5 帧 | `no-voiced-tail` |
| 浊音置信度中位数 | ≥0.65 | `low-confidence` |
| 尾区信噪比（对噪声底） | ≥4 倍 | `too-noisy` |
| 句中基线 = 句身浊音 f0 中位数（排除尾部前 100ms；句身不足 ≥300ms 时按短答句规则退回尾区） | — | `no-baseline` |
| 最后 350ms 整窗升幅（头尾各 60ms 锚点中位数差） | ≥3 半音 | `insufficient-rise` |
| 从**最后一个真低谷**（此前有 ≥1st 下滑）截起后的上升跨度 | ≥250ms 且 ≥10 帧 | `single-syllable-rise` |
| 上升段起点不得已高于基线 | ≤1.5st | `start-elevated` |
| 句末须高于基线 | ≥2 半音 | `end-not-elevated` |
| Theil–Sen 斜率（抗离群） | ≥8 半音/秒 | `insufficient-rise` |
| 回落帧占比（>0.5st 的下降） | ≤40% | `non-monotonic` |
| 相邻帧跳变 | ≤12st | `octave-jump` |

另有前置拒绝：无音频 `no-audio`、强制切段 `forced-cut`（15s 上限的切点不是语句末尾）、段长 <600ms `too-short-segment`、超预算 `budget-exceeded`。

成功时返回测量值：尾部浊音时长、上升跨度、升幅（半音）、基线 Hz、句末 Hz、置信度。

### 3.3 上文线索（toneRules.ts，仅记录）

- `findPrevQuestion`：在最近 2 句的**末尾小句**里找广义疑问线索（吗/吧/呢/什么/怎么/谁/多少/正反问/问号…），返回 ≤14 字摘录；转述句中段出现的「吗」不算前句提问；
- 上文提问**只记录进详情**（`contextPrevQuestion`），不再参与下结论：前句问过问题不代表本句在征求确认——"哪天交？"接"下周一"即使句末上扬，也最多给声音线索（本轮收紧，原"承接路径→语气提示"已删除）；
- `isShortEchoClause`（≤10 字简短附和判定）保留导出供测试，但融合决策不再使用。

## 4. 融合决策（按优先级）

**先分句**：`splitSentences` 按句末终止符（。？！?!…）划分句子，引号内不切，终止符后的闭引号归前句；末尾无终止符的片段标记为未完成。**问号只用于划界，不作为语气证据**。单句段走原有逻辑；多句段对每个完整句独立复用文本规则（`matchTextTone` 带前一句原文作跨句转述上下文）。

```
空文本 / 纯标点？ → 只留字幕（纯标点段在 liveMic 即被过滤，见 §5）
单句 + max-length 强制切段？ → 只留字幕，暂缓语气判断
多句段：
 ├─ 完整句 → 文本规则判定（命中→语气；抑制→只留字幕）
 ├─ 末尾未完成残句（含强制切段后的残句）→ 先显示字幕，暂缓判断
 └─ 音高整段测一次，仅对齐"段末完整句"（自然切段且无尾部残句）：
     前句一律不以音高为依据（not-aligned）；强制切段不测（forced-cut）
单句（自然切段）：
 文本命中确认模式？
 ├─ 是 → 语气提示「可能在征求确认」
 │        证据 = 说了「摘录」(+ 句末音高上扬，若实测成立)
 │        语音平静（平读/无音频）也凭原词提示
 ├─ 命中但被抑制（引用/反问/动作请求/嵌入式疑问/转述）
 │        → 只留字幕，连声音线索也不给，记录抑制类别与原因
 ├─ 仅实测音高上扬（无文本证据，含"前句提问+简短回答"情形）
 │        → 仅线索「句末音高上扬」，不猜语气
 └─ 其余 → 只留字幕，记录"无确认类措辞 + 音高落空原因"
```

要点：

- **文本是下结论的唯一主证据**，音高在文本命中时只作加强；
- **只有音高没有文本时最多给线索**——句末上扬也可能是二声字、情绪、回答时的语调等，不足以断定征求确认；
- 上文提问只作详情记录，不再与短句、上扬组合出语气结论。

## 5. 工程保障

- **纯标点字幕过滤**：识别结果去掉空白与标点/符号后为空（如 SenseVoice 对短噪声段输出的「。」）→ 在 liveMic 队列处理中直接移除该段，`console.info` 记录原始文本与过滤原因，不做语气分析，队列照常继续；纯标点不进字幕历史、不占「当前句」、不影响下一段显示。「本次录音识别」页签同样过滤。正常句子的问号/句号原样保留；
- 全链路 try/catch，异常 → `analysis-error`，只留字幕；
- **max-length 强制切段整体暂缓语气判断**：文本线索仍记录进详情，但不下任何结论（`pitchNullReason: 'forced-cut'`），等下一段自然收尾再判断；
- 音高分析 2 秒预算，两次检查点（粗扫后、细扫后），超时 → `budget-exceeded`；
- 空文本直接短路（`empty-text`）；
- 15 种音高落空原因均有中文标签（`pitchReasonLabel`）；5 种文本抑制类别（引号内/转述/嵌入式疑问/反问/动作请求）在 UI 详情表有对应标签，可解释"为什么没提示"；
- 迟到结果只回填原句，不产生新字幕；语气分析串行链与上传队列解耦，不阻塞后续字幕；`?tone_delay=5000` 测试钩子可人为延迟语气分析用于验收；
- 纯函数模块零依赖、仅可擦除 TS 语法，`npm test` 用 node:test 直跑单测（`scripts/test-tone-rules.ts`、`test-pitch.ts`、`test-tone-analysis.ts`、`test-live-binding.ts`——后者在 node 内 stub `window` 验证晚到绑定）。

## 6. 已知边界与待完善

- 只覆盖「征求确认」一种语气，其余语气（鼓励、批评、强调等）不做判断；
- 依赖转写文本质量：ASR 漏掉「吗/吧」或正反问结构时文本路径失效，只剩音高线索；
- 音高路径对噪声、短促句、强制切段敏感，这些场景会主动放弃（宁缺毋滥）；
- 声学情感（SenseVoice 7 类）与事件标签仅展示，不参与语气决策；
- 反问/动作请求/嵌入式疑问的标记词是枚举式启发规则，覆盖常见课堂措辞但非穷尽；新出现的误报模式需补规则与回归用例；
- **已支持：同段多句的提示绑定**（按句末终止符划界，提示挂对应句）。剩余限制：同一句内用逗号连接的多个小句（"大家能接受吗，有冲突的来找我"）仍只查末尾小句，前小句的确认问句会漏报——需要小句级时间戳或更细的绑定结构才能安全支持；
- **待完善：强制切段后的跨段续判**。max-length 暂缓后，被切断的问句若在后半段收尾，目前不会回补提示。
